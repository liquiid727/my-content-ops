## 3. six-rules — 六张保命符（6 steps · ~216s）

**画面装饰元素池**（源自 script-v2.md Ch03）：
- 保命符一反例："帮我做个登录" → 两人都沉默了 —— v2 L185-192
- 保命符一四件事：目录 / 方案 / 不能动的 / 验收标准 —— v2 L198-200
- 保命符二公式：Prompt vs Context（真正重要的是上下文）—— v2 L208-212
- 保命符二四件套：Spec / AGENTS.md / 目录结构 / 相关文件 —— v2 L221-223
- 保命符三死规矩：Diff 一定看 + 一定亲自跑 —— v2 L245-252
- 互 Review 法："开两个 Agent 让它们互相 Review" —— v2 L256-260
- 保命符四 Plan 模式四问：改哪些文件 / 几步 / 最大风险 / 其他方案 —— v2 L280-284
- 保命符五故事：二十多分钟，最后方向全错 —— v2 L294-300
- Git 四原则：小步提交 / 功能一 Commit / 大改建分支 / 出风险立即停 —— v2 L306-309
- 保命符六三信号：忘事 / 答非所问 / 改错文件 —— v2 L323-328
- 交接对比："感情债" vs "干净上下文" —— v2 L334-336

**开发计划**：

- step 1 (~35s) — 保命符一·别让 Agent 猜：登录沉默故事 → 具体需求四件事逐一揭示
- step 2 (~32s) — 保命符二·上下文要喂够：Prompt vs Context 对比 + 四件套
- step 3 (~45s) — 保命符三·Review 是你的职责：Diff 必看 → 亲自跑 → 双 Agent 互 Review
- step 4 (~32s) — 保命符四·Plan 模式先说后做：四问依次亮起，等确认再执行
- step 5 (~40s) — 保命符五·翻车不可怕可怕是回不去：20分钟故事 + Git 四原则
- step 6 (~32s) — 保命符六·主动管理上下文：三信号 → 阶段交接 → 干净开始

口播节选：
> 「我以前最喜欢一句话——帮我做个登录。然后它真的做了。做完以后，我和它两个人都沉默了。」

口播节选：

- step 3 (~47s) — 并行开发实战：三 Agent + Git Worktree 震撼体验 + 翻车案例
- step 4 (~35s) — Agent Engineering 本质：管理上下文 / 能力 / 分工 / 交接

口播节选：
> 「上下文这个东西，真的会炸。有时候你以为你在补充信息，实际上你是在往它脑子里塞购物小票。」

## 6. engineering — 工程兜底（4 steps · ~180s）

**画面装饰元素池**（源自 script-v2.md Ch06）：
- 真实故事：功能越改越顺 → 第二天核心流程挂了，页面能开/接口也回/业务悄悄歪掉 —— v2 L489-499
- Git 格言："可以不迷信模型，但一定要迷信版本控制" —— v2 L507
- 考古比喻："一口气吐出几千上万行 diff，你不是在 Review，你是在哭着考古" —— v2 L503-506
- Git 四原则：小步提交 / 功能一 Commit / 实验一分支 / 大改先退路 —— v2 L501-502
- CI 比喻："不会跟你客气的机器审查官" —— v2 L519-521
- 幻觉陷阱："进展好快，终端没报错，所以大概没事" —— v2 L525-528
- Hooks 比喻："提前埋的绊马索，在错误动作发生之前先拦一下" —— v2 L533-534
- 测试定理："看起来很对，运行也像对，但其实不对" —— v2 L545-546
- 结语大字："这场仗，我应该怎么带你打？" —— v2 L595-596

**开发计划**：

- step 1 (~40s) — Git 重要性：业务悄悄歪掉的故事 + 考古比喻 + 四原则
- step 2 (~45s) — CI + Hooks：机器审查官 + 幻觉陷阱 + 绊马索（三层安全网）
- step 3 (~45s) — 测试是最后防线：看起来对但其实不对 + 模糊愿望 vs 明确边界
- step 4 (~50s) — 总结升华：工程思维更重要了 + 问法转变大字收尾

口播节选：
> 「以后别再问 AI：你能不能帮我写完这个功能？换成：这场仗，我应该怎么带你打？这两句话的区别，真的就是这半年的区别。」
