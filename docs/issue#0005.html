Issue #0005 — Theme system and App Shell — 2026-08-09

Design Decisions

Decision Use one semantic token vocabulary across themes

Choice: Tailwind utilities resolve through HSL CSS variables for background, surfaces, text, borders, status colors, radius, shadow, and motion.

Rationale: Feature modules can express hierarchy without knowing whether light or dark values are active.

Decision Initialize theme before React mounts

Choice: A small blocking script and the runtime provider share the creator-studio-theme key and default to dark.

Rationale: The first painted frame matches the selected theme, while system mode remains reactive after mount.

Decision Hide the closed mobile drawer semantically

Choice: The off-canvas sidebar becomes visibility: hidden while closed, with desktop visibility restored at the medium breakpoint.

Rationale: Hidden navigation controls do not remain in keyboard or accessibility navigation.

Deviations

None — routing, business screens, and server-backed preference persistence remain in their dedicated later Issues.

Tradeoffs

Tradeoff Browser-local theme preference first

Alternatives: Persist theme through the settings API immediately, or keep the Foundation theme runtime self-contained.

Choice: Use local storage in this Issue and defer account/profile synchronization.

Why: This keeps FND-005 independent of later database and settings contracts while fully supporting the requested runtime modes.

Open Questions

None — all FND-005 acceptance criteria have automated or browser verification evidence.
