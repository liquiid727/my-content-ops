Implementation Notes

Issue #0011 — Frontend API client and Zustand data runtime — 2026-08-09

Design Decisions

Decision One schema-aware API boundary

Choice: Project, Asset, Settings, Task, Session, and Theme requests share one client that validates success and error envelopes, preserves request IDs, and distinguishes timeout, cancellation, network, and contract failures.

Rationale: Protocol behavior has one owner instead of four independent bootstrap/error implementations.

Decision Identity is gated and single-flight

Choice: SessionGate blocks identity-dependent routes until bootstrap succeeds; concurrent callers share the same request, and failure renders retry plus request diagnostics.

Rationale: No page can observe a partially initialized Workspace or create duplicate session requests.

Decision Local theme wins immediately

Choice: next-themes applies the selection synchronously, while a small Theme store persists it to CreatorProfile. Sync errors retain the local theme and show a notification; stale responses cannot overwrite the latest choice.

Rationale: Visual feedback is instant without sacrificing server persistence or race safety.

Deviations

Interpretation Added the missing preference write route

Spec gap: Foundation acceptance requires theme persistence in CreatorProfile, while the API endpoint table only documented reading preferences through bootstrap.

Implementation: Added the minimal PATCH /creator-profile/preferences endpoint, restricted to the shared theme schema.

Reason: This closes the explicit acceptance criterion without introducing general Profile editing.

Tradeoffs

Tradeoff Domain stores remain independent

Alternatives: A single application store would make orchestration convenient but couple identity, server snapshots, UI preferences, and event streams.

Choice: Session, Theme, Project, and Task stores expose intent actions and fine-grained selectors; the shared client owns only HTTP protocol concerns.

Tradeoff No domain Local Storage cache

Choice: Only theme remains locally persisted. Project and Task snapshots are restored from REST/SSE on refresh.

Cost: Refresh performs network reads, but it cannot display stale browser copies as authoritative data.

Open Questions

None — the narrowly scoped preference endpoint and all current data-runtime boundaries are covered by tests.
